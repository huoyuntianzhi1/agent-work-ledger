# v0.5.0 — Workspace split (Track A)

> Internal-cutover changelog covering what changed, why each
> decision was made, and what to check before shipping.

This release is **Track A** of the v0.5.0 roadmap published in
`docs/V0.5.0-ROADMAP.md`. It is a pure refactor: no schema
bump, no new connector, no IPC surface change, no user-visible
behavior change. **Track B (Stage 6 SQLCipher for `TRAE SOLO`)
ships in v0.5.x after the user grants one keychain prompt.**

---

## 1. Why this ship

The pre-split `src/lib.rs` was 2423 lines, including:

- 30+ `#[tauri::command]` handlers mixed with pure-domain logic
- The schema v3 / v4 migration (every `lib.rs` reader had to scroll past it)
- The bulk-export implementation
- The launchd install / uninstall path
- The window-state persistence (~120 lines of `tauri::WebviewWindow` glue)

This made every reading task slow, every cross-cutting
change risky (a `pub` rename rippled through 3 unrelated
subtrees), and the 47-command `generate_handler!` macro
expansion sit alongside application logic in one TU.

The v0.5.0 design (see `V0.5.0-ROADMAP.md`) committed to
splitting that single TU into 5 cohesive crates with
**clear dependency direction and zero cycles**.

---

## 2. The 5 crates

```
crates/
├── awl-core/      ← pure domain (12 modules + 10 connectors)
├── awl-db/        ← schema v4 + migration + retention
├── awl-export/    ← bulk + zip export
├── awl-ipc/       ← every #[tauri::command] + launchd glue
└── awl-desktop/   ← binary entry + Builder + tray + window state
```

### 2.1 `awl-core` — pure domain

**Has**: every module that does not need a runtime.

- `ai.rs` (LLM digest classifier + provider heuristic + Ollama probe)
- `app_settings.rs` (`awl_settings.json` read/write)
- `brief.rs` (morning brief assembly + day-over-day delta)
- `eisenhower.rs` (Q1/Q2/Q3/Q4 matrix classifier + top-3 picker)
- `error.rs` (`AppError` with `From` impls for zip / tauri / db / serde)
- `etl.rs` (per-event normalization pipeline)
- `idb.rs` (JSON side-cache)
- `planner.rs` (promote-to-daily, daily grid)
- `redactor.rs` (3 API-key patterns + cloud-provider gate)
- `reports.rs` (HTML report templates)
- `search.rs` (partition-key + payload search, FTS5 query)
- `summary.rs` (heuristic fallback)
- `connectors/` — all 10 (claude, codex, cursor, doubao, markdown_summary, minimax, opencode, trae, workbuddy)

**Deps**: `rusqlite`, `chrono`, `serde`, `walkdir`, `regex`,
`uuid`, `sha2`, `zstd`, `dirs`, `anyhow`, `thiserror`,
`tracing`, `zip`, `tauri`.

The `tauri` dep is here (and only here, transitively in
`awl-ipc` and `awl-desktop`) because `AppError::Tauri` lives
here. Moving the conversion up means downstream crates just
`use awl_core::AppError;?` and let the `From` impl bubble the
error without a per-crate wrapper.

`build.rs` runs linker-level search for the `leveldb`
symbols that Click's `state.vscdb` (Cursor plaintext stash,
added in v0.4.5) depends on.

### 2.2 `awl-db` — schema + migration + retention

**Has**:
- `lib.rs` — `SCHEMA_VERSION = 4`, `open_db`, `is_v3_schema`,
  `backup_ledger_pre_v4`, `migrate`, `migrate_for_tests` +
  `redactor_for_tests` + 6 schema tests (snapshot of v3 + v4
  row counts, idempotent re-run, retention prune after
  schema bump, batched-insert against a real SQLite file).
- `retention.rs` — `DEFAULT_RETENTION_DAYS = 90`,
  `prune_older_than(now, conn, days)` (called by launchd tick).

**Dep graph**: depends on `awl-core` (uses `redactor` + `etl`
in `migrate`).

### 2.3 `awl-export` — bulk + zip export

**Has**: the cut-down `bulk_export_session`,
`bulk_export_zip`, plus the 13 test mod (bulk group + zip
group + corrupt-zip regression).

**Dep graph**: depends on `awl-core` (uses error + etl types).
Has a **dev-only** dep on `awl-db` so the test mod can
exercise real schema plumbing without dragging `awl-db` into
runtime graph.

### 2.4 `awl-ipc` — every IPC handler

**Has**:
- 47 `#[tauri::command]`s: `health`, `list_sources`,
  `set_ai_settings`, `get_ai_settings`, `set_app_settings`,
  `get_app_settings`, `set_retention_days`, `get_retention_days`,
  `prune_now`, `run_scan_once`, `run_brief_once`,
  `auto_rescan_all`, `install_launchd`, `uninstall_launchd`,
  `summarize_text`, `render_report`, `write_pdf`, `write_zip`,
  `export_session_bulk`, `global_search`, `reset_events`,
  ... (47 total, full list in `crates/awl-ipc/src/lib.rs`)
- `run_scan_once_mode` / `run_brief_once_mode` (CLI flags)
- `auto_rescan_all` + `background_scan_loop` (scheduler)
- `launchd` install + uninstall

**Dep graph**: depends on `awl-core` + `awl-db` + `awl-export`.

**The `register<R>` wrapper**: the `#[tauri::command]` proc-macro
emits both a `pub fn X` and a private `__cmd__X` wrapper. If
two crates both `tauri::command!` the same name, the `__cmd__X`
symbol collides. The fix is to keep all 47 functions in a
single crate (here, `awl-ipc`) and **not** re-export them.
The crate exposes

```rust
pub fn register<R: tauri::Runtime>(builder: Builder<R>) -> Builder<R> {
    builder.invoke_handler(tauri::generate_handler![
        cmd_a, cmd_b, …, command_47,
    ])
}
```

which `awl-desktop::run` calls. This keeps `awl-ipc`'s
internal surface `(fn X)` private without losing the
macro expansion.

### 2.5 `awl-desktop` — binary

**Has**:
- `lib.rs` — `pub fn run()` (Builder default + setup +
  system tray + window event handlers + `awl_ipc::register`)
- `main.rs` — binary entry, parses CLI flags (`--scan-once`,
  `--brief-once`) before calling `run()`.
- `window_state.rs` — load/save window position + size. Lives
  here (not in `awl-db`) because it depends on `tauri::WebviewWindow`.

**Dep graph**: depends on `awl-core` + `awl-db` + `awl-ipc` +
`awl-export`. Pulls `tauri` 2.x and runs the actual app.

## 3. Cycle-breaking decisions

Three edges in the natural dep graph formed a cycle. Each was
broken by a concrete, documented move.

### 3.1 `app_settings` → `awl-core` (not `awl-db`)

The connectors read `awl_settings.json` to know the user's
redaction mode + Ollama endpoint + 3 API-key positions.
The schema migration also reads it (retention days is
loaded during `migrate` to decide whether to prune).

If `app_settings` lived in `awl-db`, then `awl-core`
(connector → app_settings) and `awl-db` (migrate →
app_settings) would both depend on it, and `awl-core`
would have to depend on `awl-db` (since the connectors
also use `etl::normalize` which uses `AppError` from
`awl-core`). Cycle.

Fix: lift `app_settings` to `awl-core`. `awl-db` now
depends on `awl-core` (so the migration can read
`app_settings::read` during ingest), and the connectors
get `app_settings` for free since they already live in
`awl-core`.

### 3.2 `window_state` → `awl-desktop` (not `awl-db`)

The window-state functions call `WebviewWindow::set_position`,
`WebviewWindow::set_size`, `WebviewWindow::outer_position`,
`WebviewWindow::outer_size`. Those are runtime-only
concepts that `awl-db` (a schema crate) shouldn't import.

Fix: lift `window_state` to `awl-desktop`. `awl-ipc`
never needed it directly — it only proxies state
read/write through `app_settings`, and the only consumer
that needed the runtime API was the Builder setup in
`awl-desktop::run`. The crate split moved `window_state`
to the only place that can usefully use it.

### 3.3 Two `DEFAULT_*` constants kept in lock-step

`awl_core::app_settings::DEFAULT_EVENT_RETENTION_DAYS = 90`
and
`awl_db::retention::DEFAULT_RETENTION_DAYS = 90`.

If we tried to share a single constant, `app_settings`
would have to depend on `awl-db` (cycle again), or the
retention crate would have to depend on `app_settings` in
`awl-core` (which would force `awl-db` to depend on
`awl-core` for the constant — which it does anyway, so
this one is fine).

We chose to **not** share the type and keep the value in
lock-step by a comment that points both directions:

```rust
// crates/awl-core/src/app_settings.rs
pub const DEFAULT_EVENT_RETENTION_DAYS: i64 = 90;
// Keep in lock-step with `awl_db::retention::DEFAULT_RETENTION_DAYS`.
```

```rust
// crates/awl-db/src/retention.rs
pub const DEFAULT_RETENTION_DAYS: i64 = 90;
// Keep in lock-step with
// `awl_core::app_settings::DEFAULT_EVENT_RETENTION_DAYS`.
```

If one ever drifts, the next prune will silently change its
horizon by `O(n)` days. The comment is the contract.

A similar pattern is used in `awl-core/src/ai.rs` for the
4-line `resolve_data_dir()` helper that mirrors
`awl_db::resolve_data_dir()`. Promoting either to a
shared helper would have re-introduced the
`awl-core ↔ awl-db` cycle. The duplication is intentional
and small.

## 4. What stayed the same (regression checklist)

Use this list when reviewing the diff:

- ✅ DB schema version: still `v4`. No `migrate_v4_to_v5`
  call needed. Existing `~/Library/Application Support/
  com.minimaxcode.agentworkledger/ledger.db` opens without
  migration.
- ✅ Redactor: same 3 patterns, same cloud-provider gate.
- ✅ IPC surface: every command name unchanged. `cargo test
  --workspace` covers the public schema.
- ✅ Permissions in `capabilities/default.json`: unchanged
  from v0.4.8 (`dialog:allow-save` / `allow-open` /
  `allow-message` / `allow-ask` / `allow-confirm`).
- ✅ LaunchAgent plists: same identifier, same args, same
  paths (`target/release/awl-desktop --scan-once` /
  `--brief-once`).
- ✅ Window state: same JSON layout on disk
  (`window_position.json` beside the DB). Old files
  from v0.4.6+ remain loadable.
- ✅ Bundle identifiers: `com.minimaxcode.agentworkledger`.
  Same macOS keychain entry, same launchd label, same
  audit tokens.
- ✅ Front-end (`app/src/**`): zero changes. Frontend never
  cared about the Rust crate layout.

## 6. Track B (Stage 6 SQLCipher) — next

`TRAE SOLO` keeps its conversations in
`~/Library/Application Support/TRAE SOLO/ModularData/ai-agent/database.db`,
SQLCipher-4 encrypted. The key is in the macOS keychain
under service `TRAE SOLO Safe Storage`, account equal to
the install UUID.

Track B will:

1. Add `sqlcipher = "0.14"` (C bindings) + a small
   `awl_crypto` shim for key-derivation.
2. Gate the new `trae_solo` connector on a one-time user
   prompt: `security find-generic-password -s 'TRAE SOLO
   Safe Storage' -wa` and pipe the password into
   `PRAGMA key`.
3. Render a "Locked" status card on the home page until
   the user grants access; show event counts after unlock.
4. Bump the README's connector matrix from 11 → 12 and
   `app.longDescription` accordingly.

If the user wants the full prompt UX shipped first, Track B
will ship as v0.5.1 in the same release week. If the keychain
prompt is too disruptive, it falls to v0.6.0.
